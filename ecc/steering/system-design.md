# System Design

## 核心原则

### 1. 简单性优先
- 最简单的解决方案是最好的
- 避免过度工程
- 每个组件只有一个职责

### 2. 可扩展性
- 设计时考虑未来变化
- 使用接口而非实现
- 解耦核心逻辑与外部依赖

### 3. 失败设计
- 每个外部调用都可能失败
- 实现重试机制
- 优雅降级

## 架构模式

### 分层架构
```
表现层 → 业务层 → 数据层
```
- 每层只依赖下层
- 层间通过接口通信

### 事件驱动
- 松耦合
- 可扩展
- 异步处理

## 数据库设计

### 范式选择
- OLTP: 3NF，避免冗余
- OLAP: 反范式，优化查询

### 索引策略
- 主键自动索引
- 高频查询字段加索引
- 避免过多索引（写性能）

## API 设计

### RESTful 原则
- 资源导向 URL
- HTTP 方法语义
- 状态码准确

### 版本控制
- URL 路径: /v1/, /v2/
- 向后兼容

## 缓存策略

### 缓存层次
1. CDN → 静态资源
2. 内存缓存 → 热数据
3. 分布式缓存 → 共享状态

### 缓存失效
- TTL 过期
- 主动失效
- 延迟双删
